# WebScrapeX — Technical Requirements Document

Version 2.0 · November 2026 · Implements [PRD.md](PRD.md)

## 1. Architecture

```
 Browser (React 19 client components, PWA service worker)
   │  pages: server components render HTML; client islands for console, result tabs, forms
   │  fetch() → JSON route handlers
   ▼
 Next.js 16 server (Node runtime)
   ├─ proxy.ts ............ refreshes Supabase session cookie, redirects signed-out page views to /login
   ├─ app/(app)/* ......... server components: getViewer() → getStore() → render
   ├─ app/api/* ........... route handlers (JSON), zod-validated, rate-limited
   │     └─ lib/scrape/run-job.ts ──► lib/scrape/engine.ts
   │            ├─ safe-fetch.ts  (URL normalise, SSRF guard, redirects, size/time caps)
   │            ├─ robots.ts      (RFC 9309, 15-min cache)
   │            ├─ rate-limit.ts  (per-account sliding windows, per-host politeness)
   │            ├─ browser.ts     (puppeteer-core: local Chrome / remote WS / sparticuz)
   │            ├─ selectors.ts   (field selectors, row selector, HTML tables)
   │            └─ lib/extractors/* (meta, content+Readability, SEO, social, LinkedIn, colours, fonts, tech)
   └─ lib/store/index.ts ── Store interface
         ├─ supabase.ts  → Postgres tables + Storage bucket "scrapes"   (Supabase mode)
         └─ local.ts     → .data/db.json, .data/results/*.json, .data/files/* (local mode)

 External: Supabase (Auth, Postgres, Storage) · Mailjet (OTP email) · Google Gemini (AI extract)
           · Google OAuth (via Supabase) · target websites · user webhooks · cron caller
```

Scrapes run synchronously inside the request (`maxDuration = 60`). The client shows estimated stages while it waits; the job row is created first with status `scraping`, so a run opened from another tab auto-refreshes until it completes.

## 4. Data model

Postgres (`supabase/schema.sql`), all tables RLS-enabled.

| Table | Fields | Notes |
|---|---|---|
| `websites` (Job) | `id uuid pk`, `url text`, `status text` (pending/scraping/completed/failed), `created_at`, `completed_at`, `total_assets int`, `notes text`, `user_id uuid → auth.users` | v1 table kept. `notes` holds v2 job meta JSON: `{mode, engine, title, favicon, rows, error}` |
| `metadata` | `website_id → websites`, `title`, `description`, `keywords text`, `favicon`, `color_palette jsonb`, `fonts jsonb`, `technologies jsonb` | v1 summary row, still written |
| `logs` | `website_id`, `message`, `type` (info/success/warning/error), `created_at` | job log |
| `assets` | `website_id`, `file_type`, `url` (storage path), `size_bytes` | saved images |
| `profiles` | `id → auth.users`, `full_name`, `email`, `verified` | |
| `verification_tokens` | `user_id` (sha-derived uuid of email), `token`, `expires_at` | service role only |
| `api_keys` (v2) | `id`, `user_id`, `name`, `prefix`, `key_hash unique`, `created_at`, `last_used_at` | sha256 of key |
| `schedules` (v2) | `id`, `user_id`, `url`, `options jsonb`, `frequency`, `webhook_url`, `active`, `next_run_at`, `last_run_at`, `last_job_id`, `created_at` | |

Storage bucket `scrapes` (private recommended): `<jobId>/result.json`, `<jobId>/snapshot.pdf`, `<jobId>/assets/<file>`.

**Result JSON** (`ScrapeResult`, `lib/scraper-types.ts`): `version: 2`, `url`, `options {mode, engine, fields[], rowSelector?}`, `fetch {requestedUrl, finalUrl, status, contentType, bytes, durationMs, engine, truncated}`, `robots {allowed, robotsUrl, matchedRule?, crawlDelay?, status}`, `metadata {title, description, keywords[], favicon, lang?, canonical?}`, optional `fields {columns, rows}`, `tables[]`, `headings[]`, `links[]`, `images[]`, `colors[]`, `fonts[]`, `technologies[]`, `social`, `contentAnalysis`, `linkedinProfile`, `seo`, `screenshot` (data URL), `pdfUrl`, `html` (≤ 200 KB), `warnings[]`, `completedAt`. v1 results are mapped by `upgradeV1()`.

Local mode mirrors this in `.data/db.json` (`jobs`, `logs`, `keys`, `schedules`), `.data/results/<id>.json`, `.data/files/<id>/…`, with writes serialised through a promise chain.

## 5. API contracts

All JSON errors: `{ error: string, code: string }`. Auth: cookie session, `Bearer wsx_…` key, or `Bearer <supabase access token>`; 401 `unauthorized` otherwise.

| `GET /api/v2/preflight?url=` | — | `{url, host, robots, quota{minute{used,limit}, hour{…}}}` | 400, 429 |

## 6. State, auth and validation

- **Server state** is read in server components (`getViewer()` → `getStore()`); mutations go through route handlers and `router.refresh()`.
- **Client state**: React state + react-hook-form; `useOptimistic` for history deletes; `useSyncExternalStore` for per-browser scrape defaults (`wsx:defaults` in localStorage). No global store library needed.
- **Viewer resolution** (`lib/auth.ts`): local mode → fixed local viewer (only when `localModeAllowed`); `Bearer wsx_…` → hashed key lookup; other Bearer → Supabase `getUser(token)`; else cookie session. `isAdmin` = email in `ADMIN_EMAILS`.
- **Roles**: user (own data) and admin (stats across users). All store queries filter by `user_id` even when using the service-role client; RLS covers the anon-key path.
- **Validation**: `scrapeRequestSchema` (zod) shared by console form and API; separate zod schemas for AI, assets, keys, schedules, OTP, verify; `ZodError` → 400 with field paths.

## 8. Design system implementation

See [DESIGN.md](../DESIGN.md). Tokens are CSS variables in `app/globals.css` (OKLCH, separate `:root` and `.dark` values) mapped into Tailwind with `@theme inline` (`bg-card`, `text-primary-ink`, …). Fonts: Bricolage Grotesque (display, variable), IBM Plex Sans 400/500/600, IBM Plex Mono 400/500, self-hosted with `next/font/local`. Components in `components/ui` wrap Radix primitives with project styling (button variants, field controls, badges, dialog/sheet, menu, tabs, switch, tooltip). Motion: 150–300 ms ease-out-quart; `MotionConfig reducedMotion="user"` plus a CSS reduced-motion override.

## 9. PWA

- `app/manifest.ts`: id/scope `/`, standalone, background `#f8f6f1`, theme `#16181d`, icons 192/512/maskable-512, shortcuts (New scrape, History). `app/apple-icon.png` 180 px; `viewport.themeColor` per colour scheme.
- `app/sw.ts` (Serwist): precache build manifest + `/offline`; `NetworkOnly` for same-origin `/api/*` and `/auth/*`; Serwist `defaultCache` for pages (network-first), static assets and images; document fallback → `/offline`. Disabled in `next dev`.
- Output `public/sw.js` is git-ignored and generated at build.

## 10. Performance, security, testing, deployment

**Performance budget:** first-load JS per page ≤ ~200 KB gzip; fonts self-hosted with `display: swap`; command menu dynamically imported; `optimizePackageImports` for lucide/radix; heavy server libs (`puppeteer-core`, `jsdom`, `@sparticuz/chromium-min`) in `serverExternalPackages`.

**Security:** headers (`X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: DENY`, `Permissions-Policy`); SSRF guard + redirect re-checks; robots enforcement; zod on every body; rate limits (§F-10); keys hashed; CSV formula escaping; file responses sandboxed; `next` redirects restricted to same-origin paths; timing-safe cron secret comparison; no stack traces in API errors.

**Testing strategy (this release):** `npm run typecheck`, `npm run lint` and `npm run build` must pass; manual verification in a production build in local mode (scrape → result → export → history → delete; robots-blocked URL; private-IP URL; rate-limit 429; mobile/desktop, light/dark). Recommended next step: unit tests for `robots.evaluate`, `selectors.runFieldSelectors`, `export.toCsv` and `rate-limit.take` (pure functions, no network).

**Deployment:** Vercel (`vercel.json` daily cron) or any Node host (`npm run build && npm start`). Netlify config kept (`netlify.toml`). Run `supabase/schema.sql` once.
